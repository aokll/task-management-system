Шаг 2: Создание «Чертежа» (Dockerfile)
Это инструкция: «Как собрать компьютер для этой программы».

•	Содержание: Берем образ с Java (FROM), создаем папку (WORKDIR), кладем туда наш JAR (COPY) и говорим, как его запустить (ENTRYPOINT).

В корне твоего проекта (там, где папки src, target и файл pom.xml) создай новый файл и назови его просто Dockerfile (без расширения).
Вставь в него этот код:
dockerfile
# Используем легкий образ с Java 21 (или твоей версией)
FROM eclipse-temurin:21-jdk-alpine

# Указываем рабочую папку внутри контейнера
WORKDIR /app

# Копируем наш скомпилированный JAR внутрь образа
COPY target/*.jar app.jar

# Команда, которая запустит приложение при старте контейнера
ENTRYPOINT ["java", "-jar", "app.jar"]
Используйте код с осторожностью.

Шаг 3: Командный центр (docker-compose.yml)
Это сценарий для целого «аквариума» контейнеров.
•	Зачем: Чтобы одним кликом запустить и Базу Данных, и Приложение, и соединить их невидимым «кабелем» внутри сети Docker.
•	Ключевой момент: В настройках Java мы пишем адрес базы не localhost, а db (имя сервиса из файла).

Сейчас твоя Java-программа и база данных Postgres живут отдельно. Чтобы они «увидели» друг друга внутри Докера, нам нужен файл-сценарий.
В корне проекта (рядом с Dockerfile) создай файл docker-compose.yml. Вставь туда этот код:
yaml
version: '3.8'

services:
  # Наша база данных
  db:
    image: postgres:15
    container_name: postgres_db
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: tasks_db
    ports:
      - "5433:5432" # Прокидываем порты (внешний 5433, внутренний 5432)

  # Наше Spring Boot приложение
  app:
    build: .
    container_name: java_app
    ports:
      - "8081:8080" # Твое приложение будет доступно на http://localhost:8081
    depends_on:
      - db
    environment:
      # Магия! Указываем Java, что база находится по имени сервиса "db"
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/tasks_db
      SPRING_DATASOURCE_USERNAME: user
      SPRING_DATASOURCE_PASSWORD: password
      SPRING_JPA_HIBERNATE_DDL_AUTO: update
Используйте код с осторожностью.
В чем здесь «Ход конем»? ♟️
•	depends_on: Мы говорим Докеру: «Сначала запусти базу, а потом приложение».
•	SPRING_DATASOURCE_URL: Внутри Докера твоя программа ищет базу не по адресу localhost, а по имени сервиса — db. Это их внутренняя рация [4].

Технический отчет: Этап 6 — Spring Security & Auth (v6.5)
1. Слой данных (Entity & Database)
Мы создали две таблицы: users (кто заходит) и user_role (что ему можно).
Почему Set<Role>? Чтобы у пользователя могло быть несколько прав (например, и USER, и ADMIN), и они не дублировались.
Unique Constraint: Поле username помечено как уникальное на уровне базы. Если кто-то попытается создать второго admin, база данных сама «выбросит» ошибку, защищая систему.

2. Шифрование (BCrypt)
В SecurityConfig мы добавили BCryptPasswordEncoder.
Как это работает: Когда ты вводишь 12345, BCrypt превращает его в строку типа $2a$10$v....
Зачем: Даже если хакер украдет твою базу данных, он не узнает пароли. BCrypt специально сделан медленным, чтобы его нельзя было взломать простым перебором.

3. Мост к базе (UserDetailsService)
Это был самый важный «невидимый» элемент.
Проблема: Spring Security по умолчанию ищет пользователей в оперативной памяти.
Решение: Мы создали UserDetailsServiceImpl. Теперь, когда ты жмешь «Login», Спринг идет в этот сервис, тот делает запрос в UserRepository, находит твоего admin в PostgreSQL и возвращает его Спрингу.
Префикс ROLE_: Спринг требует, чтобы роли внутри системы назывались именно так (ROLE_ADMIN). Мы добавляем этот префикс «на лету» в коде сервиса.

4. Цепочка фильтров (SecurityFilterChain)
Это твой «КПП» на въезде в приложение.
.anyRequest().authenticated() — команда закрыть вообще всё. Пока не покажешь «паспорт» (не залогинишься), дальше контроллера TaskViewController тебя не пустят.
.formLogin(withDefaults()) — команда Спрингу: «Сгенерируй стандартную HTML-форму логина и лови данные, которые в неё введут».

5. Инициализация (CommandLineRunner)
Мы автоматизировали создание «первого ключа».
При старте приложение проверяет: «Есть ли админ?».
Если нет — создает его, шифрует пароль и кладет в базу. Это гарантирует, что ты не окажешься перед закрытой дверью в пустой системе.
