# Java Tracker — Ver 6.0: Multi-user Logic

## Что нового в этой версии? (Diff: 5.0 -> 6.0)

В шестой версии проект совершил качественный скачок: из одиночного приложения он превратился в 
**многопользовательскую платформу**. Теперь каждый пользователь живет в своем изолированном пространстве.

### 1. Архитектура "Владения" (Ownership)
*   **Связь сущностей:** В сущность `Task` добавлено поле `User owner` с аннотацией `@ManyToOne`. Это связало таблицы в БД через Foreign Key (`user_id`).
*   **Изоляция данных:** Теперь методы `findAll()` заменены на фильтрацию по владельцу. Пользователь "Амиго" больше не видит задачи "Админа".
*   **Автопривязка:** При создании задачи (`addTask`) сервис автоматически определяет текущего пользователя через сессию и назначает его владельцем.

### 2. Безопасность на молекулярном уровне
*   **Защита от ID-перебора (IDOR):** Реализована проверка прав доступа в Service Layer. Даже если изменить ID в адресной строке, система не позволит удалить или отредактировать чужую задачу.
*   **Security Context Integration:** Сервис научился напрямую общаться с `SecurityContextHolder`, чтобы получать данные о текущем сеансе без передачи `username` во фронтенд.
*   **CSRF Protection:** Временно отключен CSRF-фильтр в `SecurityConfig` для обеспечения стабильной работы REST-методов и POST-форм на этапе отладки.

### 3. Рефакторинг Persistence Layer (Repository)
*   **Derived Queries:** В `TaskRepository` внедрены сложные методы поиска, учитывающие владельца:
    *   `findByOwnerUsernameAndTitleContainingIgnoreCase`
    *   `findByOwnerUsernameAndStatusOrderByLevelDesc`
*   **Оптимизация:** Сортировка по уровню теперь происходит на стороне базы данных (SQL `ORDER BY`), а не в оперативной памяти Java.

## Технический стек этапа
*   **Spring Security:** Контроль доступа на уровне методов сервиса.
*   **Hibernate:** Настройка связей `@ManyToOne(fetch = FetchType.LAZY)`.
*   **PostgreSQL:** Обновленная схема данных с внешними ключами.

## Как проверить работу версии 6.0
1.  **Запустите приложение** (таблицы пересоздадутся автоматически благодаря `ddl-auto: update`).
2.  **Войдите под `admin` (пароль 12345):** Создайте задачу "Секретный план".
3.  **Выйдите и войдите под `amigo` (пароль java):**
    *   Убедитесь, что список задач пуст.
    *   Попробуйте вызвать `/api/tasks/delete?id=1` (где 1 — ID задачи админа) — система должна заблокировать действие.
4.  **Создайте задачу под `amigo`:** Убедитесь, что она отображается только в его профиле.

## Решенные проблемы (Troubleshooting)
*   **Infinite Recursion:** Использован `@ToString(exclude = "owner")` для предотвращения циклической зависимости между Task и User при логировании.
*   **Invalid DDL:** Решена проблема с добавлением колонки `NOT NULL` в существующую таблицу через полную очистку таблиц (`DROP TABLE`) или использование режима `create-drop`.
