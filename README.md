# JavaTracker

## Этап 13: Database Migrations (Flyway Integration)

На данном этапе в проект была интегрирована система миграции базы данных. 

---

### Два способа внедрения Flyway в Spring Boot

#### Способ 1: Декларативный
Классический подход, заложенный создателями Spring Boot, где параметры прописываются декларативно.
* **Как это работает** — Spring Boot сканирует classpath и автоматически создает бин `FlywayMigrationInitializer`.
* **Цепочка запуска** — встроенный инициализатор принудительно срабатывает строго до старта Hibernate.
* **Плюсы фреймворка** — обеспечивает полное отсутствие шаблонного Java-кода.

#### Способ 2: Программный
Архитектурный подход для полного ручного контроля над жизненным циклом СУБД.
* **Как это работает** — создается изолированный конфигурационный компонент `DatabaseMigrator.java` 
* с аннотацией `@Component`.
* **Цепочка запуска** — триггер `@PostConstruct` выполняет миграцию сразу после готовности фабрики сущностей, 
* блокируя запуск валидации Hibernate.
* **Плюсы решения** — абсолютная независимость от скрытых механизмов автоконфигурации фреймворка и кэша Maven.
* **Гибкость кода** — позволяет организовать ручной перехват критических ошибок сборки схемы через блоки `try-catch`.

### Стек технологий проекта

#### Базовый стек:
* **Java 17 / 21** — современный LTS-релиз с поддержкой Stream API и Concurrency.
* **Spring Boot 3.x** — основа бэкенд-инфраструктуры и контейнера бинов.
* **Spring Data JPA & Hibernate** — объектно-реляционное отображение (ORM) и слой репозиториев.
* **Spring Security** — ограничение доступа (роли USER, ADMIN) и шифрование паролей (BCrypt).
* **PostgreSQL 15** — целевая локальная реляционная система управления базами данных.
* **Docker & Docker Compose** — контейнеризация изолированного окружения базы данных и приложения.
* **Thymeleaf & Bootstrap 5** — шаблонизатор и фронтенд-фреймворк для построения Web UI.
* **Lombok & JUnit 5 / Mockito** — автоматическая генерация кода, модульное тестирование и создание моков.

#### Добавлено на 13 этапе:
* **Flyway Core** — независимый миграционный движок с управлением через Fluent Java API.
* **PostgreSQL Dialect SQL** — чистые скрипты DDL/DML для физического развертывания структуры таблиц.

### Что добавилось на данном этапе:

1.  **Жесткий контроль схемы:**
    * Свойство `ddl-auto` переведено в режим `validate`.
    * Hibernate полностью лишен прав на изменение таблиц в СУБД.
    * Осуществляется только строгая проверка соответствия сущностей структуре базы данных.

2.  **Программная стратегия отсчета:**
    * Параметры `baselineOnMigrate` перенесены из конфигурационных файлов в Java-код.
    * Инициализация Fluent API Flyway защищает живую базу от падения.
    * Создается служебная таблица истории с нулевой точкой отсчета.

3.  **Отказоустойчивый SQL-скрипт (`V1__Init_DB.sql`):**
    * Написан чистый SQL-скрипт развертывания таблиц `users`, `tasks` и `user_role`.
    * Внедрен составной первичный ключ для защиты коллекции ролей от дубликатов.
    * Настроено каскадное удаление `ON DELETE CASCADE` для связей Many-to-One.

4.  **Разделение окружений (Local vs Docker):**
    * Локальный сервер полностью переведен под управление программного Flyway.
    * Docker-контейнер изолированно использует классический режим автоматического обновления `update`.
    * Данное разделение гарантированно защищает контейнеризацию от "состояния гонки" при старте.

### Проверка работоспособности кода

Для демонстрации работы миграции необходимо полностью очистить локальную базу данных через терминал `psql`:
```bash
\c postgres
SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = 'javarush_tracker' AND pid <> pg_backend_pid();
DROP DATABASE IF EXISTS javarush_tracker;
CREATE DATABASE javarush_tracker;
```

#### Ожидаемый результат при старте приложения (IntelliJ IDEA):
* В консоли отобразится лог: `>>> СИЛОВОЙ АВТОНОМНЫЙ СТАРТ МИГРАЦИИ FLYWAY <<<`.
* Выведется системный отчет Flyway о физическом создании таблиц.
* Миграция выполнится строго один раз силами кастомного Java-движка.

#### Проверка структуры СУБД (изнутри базы данных):
Для верификации результата необходимо зайти в терминал `psql` и подключиться к целевой базе:
```sql
\c javarush_tracker
\dt
```
* **Результат команды `\dt`** — терминал выведет список из 4 таблиц 
* (`users`, `tasks`, `user_role`, `flyway_schema_history`).

```sql
SELECT * FROM flyway_schema_history;
```
* **Результат запроса SELECT** — выведется строка с версией `1` и хэш-кодом (checksum) файла, 
* подтверждающая свойство полной идемпотентности Flyway.

Проект полностью избавлен от неконтролируемой генерации таблиц силами JPA/Hibernate на локальном сервере.
