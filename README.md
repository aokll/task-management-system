# Java Task Tracker (Multi-user Edition)

Персональный трекер задач на языке Java, построенный на стеке **Spring Boot + PostgreSQL**. Приложение гарантирует полную изоляцию данных: каждый пользователь управляет исключительно своими целями и задачами.

---

## Технологический стек

*   **Backend:** Java 17, Spring Boot 3 (Data JPA, Security, Web, Validation)
*   **Database:** PostgreSQL (Hibernate ORM)
*   **Security:** Spring Security (Шифрование паролей через BCrypt)
*   **Frontend:** Thymeleaf + Bootstrap 5 (WebJars)
*   **Utils:** Lombok, Maven

---

## Что добавилось на 10 этапе

На этом этапе приложение перешло от простого накопления данных к полноценному управлению их жизненным циклом (Update).

1.  **Функционал Update (CRUD):** Реализована возможность изменять название, уровень, тему и сложность уже созданных задач.
2.  **Адресная REST-логика:** Внедрена работа с ресурсами через динамические URL-адреса (`/edit/{id}`) с использованием аннотации `@PathVariable`.
3.  **Двухфазный процесс редактирования:**
    *   **GET-фаза:** Безопасное извлечение состояния объекта и предзаполнение формы данными из DTO.
    *   **POST-фаза:** Прием измененных параметров и синхронизация с БД через механизм *Dirty Checking* в Hibernate.
4.  **Security-фильтрация:** Внедрена проверка прав владения на уровне сервиса. Теперь редактирование доступно только владельцу задачи, что защищает от IDOR-атак (подмена ID в URL).

## Инструкция по проверке

#### 1. Тест «Кругосветное путешествие данных»
*   **Действие:** Нажать кнопку **«Изменить»** на любой задаче.
*   **Результат:** Открывается форма с корректно предзаполненными данными. После правки названия и сохранения Dashboard отображает обновленную карточку.
*   **Смысл:** Проверка полной цепочки запроса: `GET (Read)` -> `UI` -> `POST (Update)` -> `SQL UPDATE`.

#### 2. Тест «Хирургическая точность»
*   **Действие:** Изменить только одно поле (например, сложность с `MEDIUM` на `HARD`).
*   **Результат:** Бейдж на карточке стал красным (`HARD`), остальные поля (название, тема) остались нетронутыми.
*   **Смысл:** Проверка точечной работы сеттеров и сохранения консистентности объекта в базе.

#### 3. Тест «Крепость Монолита» (Защита IDOR)
*   **Действие:** Попытаться зайти на страницу редактирования чужой задачи, вручную изменив ID в адресной строке (например, с `/edit/10` на `/edit/11`).
*   **Результат:** Система выдает ошибку или отказ в доступе, не показывая чужие данные.
*   **Смысл:** Проверка работы фильтра безопасности `.filter(task -> task.getOwner()...)` в сервисном слое.

#### 4. Тест «Память выбора»
*   **Действие:** Открыть форму редактирования существующей задачи.
*   **Результат:** В выпадающем списке сложности автоматически выбрано то значение, которое было сохранено ранее (благодаря `th:selected`).
*   **Смысл:** Подтверждение корректной связи строкового значения из DTO с Java Enum на уровне фронтенда.

## Установка и запуск

1.  **База данных:** Создайте базу `javarush_tracker` в PostgreSQL.
2.  **Конфигурация:** Настройте `username` и `password` в файле `src/main/resources/application.yaml`.
3.  **Запуск:** Запустите основной класс `DemoApplication.java`.
4.  **Доступ:** Для тестирования админ-функций используйте логин `superadmin` и пароль `12345`.
