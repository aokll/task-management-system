# JavaTracker

## Этап 15: Logging Architecture (Архитектура логирования на базе SLF4J + Logback)

---

### Стек технологий проекта

#### Базовый стек:
* **Java 17/21** — Сердце бэкенда
* **Spring Boot 4 (Data JPA, Web, Thymeleaf, Security, Validation)** — Корневой каркас
* **PostgreSQL** — Реляционная база данных
* **Flyway** — Инструмент автоматической миграции БД
* **Springdoc-OpenAPI 3 (Swagger)** — Интерактивная документация API
* **Docker / Docker Compose** — Контейнеризация приложения и инфраструктуры
* **Lombok** — Автоматическая генерация кода (Boilerplate reduction)

#### Добавлено на 15 этапе:
* **SLF4J (Simple Logging Facade for Java)** — Стандартизированный фасад для изоляции логирования 
* от конкретных библиотек
* **Logback** — Производительный, промышленный движок логирования (реализация SLF4J)
* **MDC (Mapped Diagnostic Context)** — Технология трассировки и привязки контекстных данных 
* (username) к текущим потокам
* **Spring TaskDecorator** — Инструмент для сквозного переноса контекста логирования между 
* Web-потоками и асинхронным пулом

---

### Что добавилось на данном этапе:

1. **Централизованная конфигурация (`logback-spring.xml`)**
   Полностью вычищен хаотичный и блокирующий вывод через `System.out.println`. 
   Внедрен гибкий конфигурационный центр, разделяющий потоки логов:
   * **CONSOLE** — Цветной структурированный вывод логов (`%highlight`, `%cyan`) 
   * с указанием времени, потока и бизнес-контекста для локальной разработки (`dev`).
   * **FILE (RollingFileAppender)** — Отказоустойчивый логер для production-окружения. 
   * Защищает диск сервера от переполнения с помощью политики `SizeAndTimeBasedRollingPolicy`: 
   * автоматическая ротация логов по дням, сжатие старых файлов в `.gz`, 
   * лимит размера одного файла в 10MB и жесткий потолок на общий архив в 1GB (хранение истории за 30 дней).

2. **Сквозная асинхронная трассировка (MDC + TaskDecorator)**
   Решена фундаментальная проблема многопоточных систем (из Этапа 11 Concurrency) — перемешивание 
логов при одновременной работе сотен пользователей. Внедрен кастомный `MdcTaskDecorator`, 
который при передаче «тяжелой» задачи на анализ в асинхронный пул потоков (`JavaTracker-Async-`) 
принудительно копирует `ThreadLocal` карту памяти MDC из родительского Web-потока Tomcat. 
Каждая строчка лога в фоновом режиме теперь жестко промаркирована именем пользователя `[%X{username}]`,
запустившего процесс. Реализована гарантированная очистка контекста потока в блоке `finally` 
для исключения утечек памяти.

3. **Строгая типизация и параметризация (`@Slf4j`)**
   Все сервисы переведены на использование аннотации `@Slf4j` от Lombok. 
Логирование переписано с использованием производительных плейсхолдеров `{}` (параметризованный вывод) 
вместо конкатенации строк. Это предотвращает лишнее выделение памяти в Heap и экономит ресурсы CPU, 
так как строка лога собирается компилятором только в случае, если данный уровень логирования активен.

4. **Архитектурное разделение по уровням (Logging Levels)**
   * `DEBUG` — Техническая трассировка поисковых запросов и входящих параметров методов контроллера.
   * `INFO` — Главные вехи приложения (успешная регистрация пользователей, создание и штатное обновление задач).
   * `WARN` — Фиксация потенциально деструктивных действий (старт удаления, отклонение смены статуса 
   из-за Race Condition).
   * `ERROR` — Бизнес-ошибки (задачи не найдены в БД) и критические инциденты безопасности 
   (попытка несанкционированного удаления/изменения чужих данных).

5. **Аудит критических операций в Админ-панели**
   Реализовано сквозное логирование деструктивных действий (удаление пользователей). 
Перед вызовом каскадного удаления через Hibernate, метод контроллера принудительно инициализирует 
контекст `MDC.put("username", adminName)` и извлекает имя целевого пользователя по ID. 
Это гарантирует фиксацию инцидента безопасности с указанием авторов и жертв операции, 
даже если вызов репозитория идет в обход стандартного сервисного слоя. 
По окончании запроса контекст изолированно очищается через `MDC.clear()`.

### Проверка работоспособности кода

#### 1. Логирование инициализации (CommandLineRunner):
При старте приложения в консоли и файле `logs/javatracker.log` фиксируется системный прогрев:
```text
2026-06-13 15:00:05.120 [main] INFO  [] com.example.demo.DataInitializer - --- СУПЕР-АДМИН СОЗДАН (логин: admin, пароль: admin) ---
2026-06-13 15:00:05.450 [main] INFO  [] com.example.demo.LineRunner - >>> Пользователь 'amigo' создан (пароль: java)!
```

#### 2. Работа сквозного MDC логера в асинхронном режиме:
Когда пользователь `amigo` нажимает кнопку «Выполнить задачу», лог наглядно показывает бесшовный перенос контекста между абсолютно разными потоками операционной системы:
```text
2026-06-13 15:10:02.100 [http-nio-8080-exec-3] INFO  [amigo] com.example.demo.service.TaskServiceImpl - Задача #5 переведена в статус ANALYZING. Передача в асинхронный движок анализа.
2026-06-13 15:10:02.105 [JavaTracker-Async-1] INFO  [amigo] com.example.demo.service.TaskAnalysisService - Фоновый поток запущен. Начало тяжелого анализа для задачи ID #5
2026-06-13 15:10:07.110 [JavaTracker-Async-1] INFO  [amigo] com.example.demo.service.TaskAnalysisService - Фоновый анализ завершен УСПЕШНО. Статус задачи #5 изменен на DONE
```

#### 3. Предотвращение инцидентов безопасности (Уровень ERROR):
Если злоумышленник пытается отправить POST-запрос на удаление чужого ID задачи, система блокирует действие и фиксирует нарушение:
```text
2026-06-13 15:12:40.890 [http-nio-8080-exec-5] ERROR [hacker_user] com.example.demo.service.TaskServiceImpl - НАРУШЕНИЕ БЕЗОПАСНОСТИ! Пользователь [hacker_user] пытается удалить чужую задачу #5
```
#### 4. Логирование деструктивных действий администратора:
При удалении пользователя из админ-панели, система генерирует предупреждение уровня `WARN` 
перед началом транзакции и фиксирует успешный результат уровнем `INFO`, наглядно демонстрируя связь логов и 
SQL-каскадов Hibernate:
```text
2026-06-13 17:18:24.515 [http-nio-8080-exec-10] WARN  [superadmin] c.e.demo.controller.AdminController - АДМИН ПАНЕЛЬ: Администратор [superadmin] инициировал полное удаление пользователя [user] (ID #N)
Hibernate: delete from user_role where user_id=?
Hibernate: delete from users where id=?
2026-06-13 17:18:24.520 [http-nio-8080-exec-10] INFO  [superadmin] c.e.demo.controller.AdminController - АДМИН ПАНЕЛЬ: Пользователь [user] (ID #N) успешно удален из системы администратором [superadmin]
```

### Вывод:
Внедрение профессиональной архитектуры логирования на базе **SLF4J + Logback + MDC** 
превратило проект из слепого монолита в прозрачную, полностью контролируемую систему (Observability). 
Приложение готово к развертыванию в контейнерах и интеграции с промышленными системами сбора и анализа логов 
(ELK Stack / Grafana Loki), обеспечивая мгновенный аудит безопасности и трассировку багов в многопоточной среде.
