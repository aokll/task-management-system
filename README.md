# Java Task Tracker (Multi-user Edition)

Персональный трекер задач на языке Java, построенный на стеке **Spring Boot + PostgreSQL**.
Приложение поддерживает полноценную регистрацию и гарантирует, что каждый пользователь работает только
со своим списком задач.

---

## Технологический стек

*   **Backend:** Java 17, Spring Boot 3 (Data JPA, Security, Web, Validation)
*   **Database:** PostgreSQL (реляционная база данных)
*   **Security:** Spring Security (шифрование паролей через BCrypt)
*   **Frontend:** Thymeleaf + Bootstrap 5 (адаптивная верстка)
*   **Utils:** Lombok, Maven

---

## Требования

*   **Java:** 17+
*   **Maven:** 3.6+
*   **PostgreSQL:** 14+

---

## Основные функции

1.  **Система регистрации и входа:**
    *   Безопасное хранение паролей в хешированном виде.
    *   Автоматическое назначение ролей (`USER`).
2.  **Изоляция данных (Multi-user Logic):**
    *   Пользователи не могут видеть или удалять задачи друг друга.
    *   Автоматическая привязка новых задач к текущему авторизованному аккаунту.
3.  **Умный Dashboard:**
    *   Динамический расчет прогресса обучения (в процентах).
    *   Цветовая индикация сложности задач (EASY, MEDIUM, HARD).
    *   Удобное управление: добавление, удаление и отметка "Готово" в один клик.
4.  **Валидация:**
    *   Контроль ввода: названия от 3 до 50 символов, уровни строго 0–40.
5.  **Статус API:**
    *   Приложение поддерживает не только Web-интерфейс, но и REST API для внешних интеграций.

---

### Что было добавлено на 8 этапе:

*   **Админ-панель:** Создан защищенный раздел `/admin/users` для управления списком пользователей.
*   **Управление ролями:** Реализовано разграничение прав доступа. Кнопка управления пользователями видна только аккаунтам с ролью `ADMIN`.
*   **Каскадное удаление:** Настроена связь `@OneToMany(cascade = CascadeType.ALL)`. При удалении пользователя база данных автоматически очищает все его задачи.
*   **Безопасный Logout:** Внедрена корректная процедура выхода из системы через POST-запрос.
*   **Обработка дубликатов:** Добавлена логика проверки уникальности логина при регистрации с выводом ошибки пользователю.

## Структура проекта

*   `entity/` — описание таблиц БД (User, Task).
*   `repository/` — интерфейсы для работы с БД через Spring Data JPA.
*   `service/` — бизнес-логика (расчет прогресса, управление пользователями).
*   `controller/` — обработка запросов (Web UI, Admin UI и REST API).
*   `config/` — настройки безопасности и инициализация данных.

---

## Запуск проекта

1.  **База данных:** Создайте базу в PostgreSQL:
    ```sql
    CREATE DATABASE javarush_tracker;
    ```
2.  **Настройки:** Укажите ваш логин и пароль в `src/main/resources/application.yaml`.
3.  **Запуск:** Запустите основной класс `DemoApplication`.
4.  **Доступ:** `http://localhost:8080/register`

### Инструкция по проверке работоспособности (Этап 8)

#### 1. Проверка «Супер-силы» (Админка)
*   **Действие:** Зайди под пользователем `superadmin` (пароль `12345`).
*   **Что искать:** На главном Dashboard должна появиться оранжевая кнопка **«⚙️ УПРАВЛЕНИЕ ПОЛЬЗОВАТЕЛЯМИ»**.
*   **Тест:** Нажми на неё. Ты должен попасть на страницу `/admin/users`. Если открылся список пользователей — Spring Security правильно распознал твою роль `ADMIN`.

#### 2. Проверка «Границ» (Обычный юзер)
*   **Действие:** Нажми `Logout` и зайди под обычным пользователем.
*   **Что искать:** На Dashboard кнопки админки **быть не должно**.
*   **Тест на «взлом»:** Вручную введи в адресной строке браузера: `http://localhost:8080/admin/users`.
*   **Результат:** Тебя должно либо выкинуть на страницу ошибки **403 Forbidden**, либо перенаправить на страницу логина. Если так — защита путей работает!

#### 3. Проверка «Эффекта Домино» (Каскадное удаление)
*Это самая важная проверка связи `@OneToMany(cascade = CascadeType.ALL)`.*

1.  Зайди под `superadmin`.
2.  Посмотри, есть ли в списке пользователь `amigo`.
3.  **Важно:** Перед удалением убедись (в базе или зайдя под ним), что у `amigo` есть хотя бы одна созданная задача.
4.  Нажми **«Удалить»** напротив `amigo`.
5.  **Результат в базе:** Проверь таблицу `users` (пользователь удален) и таблицу `tasks`. Если задачи, принадлежавшие `amigo`, исчезли вместе с ним — значит, каскадное удаление настроено идеально. База чиста, «сирот» не осталось.

#### 4. Проверка «Защиты от дублей» (Регистрация)
*   **Действие:** Перейди на страницу `/register`.
*   **Тест:** Попробуй создать пользователя с именем `admin` (которое уже занято в системе).
*   **Результат:** Страница должна перезагрузиться и показать красную надпись: *"Логин 'admin' уже занят..."*. Если аккаунт не создался повторно — твоя проверка в `RegistrationController` работает корректно.
