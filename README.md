# JavaTracker

**JavaTracker** — это высокопроизводительный трекер задач, который не просто хранит ваши цели, но и умеет обрабатывать их в фоновом режиме, имитируя работу реальных Enterprise-систем.

---

## Технологический стек этапа
*   **Concurrency:** Spring Async, ThreadPoolTaskExecutor (управляемый пул потоков).
*   **Safety:** `synchronized` методы для предотвращения Race Condition.
*   **Persistence:** Hibernate `saveAndFlush` для немедленной синхронизации состояния.
*   **Architecture:** Слой DTO, Mapper, полная изоляция данных через SecurityContext.

---

## Что мы добавили на 11 этапе:

На этом этапе мы научили наше приложение работать «в два ума», разделяя действия пользователя и тяжелые фоновые вычисления.

1.  **Асинхронный движок (Spring Async):** Внедрена поддержка фоновых задач через `@Async`. Теперь тяжелый «анализ» задачи не заставляет пользователя ждать — страница Dashboard перезагружается мгновенно, пока сервер трудится в фоне.
2.  **Управляемый пул потоков (Thread Pool):** Создан кастомный `ThreadPoolTaskExecutor` (Core: 2, Max: 5). Это защищает сервер от неконтролируемого плодения потоков и перегрузки ресурсов.
3.  **Защита от Race Condition:** Методы сервиса защищены ключевым словом `synchronized`. Это исключает конфликты и ошибки `DataIntegrityViolationException` при быстром двойном клике на одну и ту же задачу.
4.  **Молекулярная зачистка (Refactoring):**
    *   **DTO везде:** Все методы поиска и выдачи данных теперь возвращают только `TaskDto`.
    *   **DRY (Don't Repeat Yourself):** Создан единый приватный механизм `getCurrentUsername()` для получения личности пользователя из защищенной памяти Spring Security.
    *   **Чистые контроллеры:** Из `TaskController` и `TaskViewController` полностью удалены репозитории. Вся работа идет строго через `TaskService`.

## Инструкция по проверке

#### 1. Тест «Асинхронный запуск»
*   **Действие:** Нажать кнопку **«Готово»** на Dashboard.
*   **Ожидаемый результат:** Страница обновляется мгновенно. Статус задачи меняется на `ANALYZING`.
*   **Логи:** В консоли IDEA появляется запись от потока `JavaTracker-Async-X`: *«Начат анализ задачи...»*.
*   **Молекулярный смысл:** Подтверждение того, что основной поток (Tomcat) освободился, а задача ушла в отдельный поток пула.

#### 2. Тест «Фоновое завершение»
*   **Действие:** Подождать 5 секунд и обновить страницу Dashboard.
*   **Ожидаемый результат:** Статус задачи автоматически сменился с `ANALYZING` на `DONE`.
*   **Логи:** Запись *«Статус задачи обновлен на DONE в фоновом потоке»*.
*   **Молекулярный смысл:** Проверка способности фонового потока самостоятельно управлять транзакциями и обновлять базу данных.

#### 3. Тест «Защита от Race Condition»
*   **Действие:** Быстро нажать кнопку «Готово» два-три раза подряд.
*   **Ожидаемый результат:** Приложение не «падает» с ошибкой 500. Все запросы, кроме первого, мягко обрабатываются системой.
*   **Молекулярный смысл:** Проверка блокировки метода через `synchronized` и атомарности операции в базе через `saveAndFlush`.

#### 4. Тест «Архитектурная стерильность»
*   **Действие:** Вызвать метод поиска через API (`/api/tasks/all`).
*   **Ожидаемый результат:** JSON-ответ содержит только плоские поля `TaskDto`. Данные владельца (User) представлены только именем, без паролей и ролей.
*   **Молекулярный смысл:** Гарантия того, что рефакторинг полностью изолировал доменную модель от внешнего мира.
