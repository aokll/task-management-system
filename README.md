# JavaTracker

## Этап 12: Testing & Lombok Foundation
**Цель этапа:** Внедрение модульного тестирования и очистка кода от 
шаблонного мусора с помощью Lombok.

---

### Стек технологий проекта

#### Базовый стек:
*   **Java 17** (Core, Streams, Optional)
*   **Spring Boot 3.x / 4.x** (Web, Data JPA, Security)
*   **PostgreSQL** (Основная БД)
*   **Thymeleaf & Bootstrap 5** (UI Layer)

#### Добавлено на 12 этапе (Testing & DevTools):
*   **Lombok:** Библиотека для автоматической генерации байт-кода (геттеры, сеттеры, билдеры).
*   **JUnit 5:** Современный фреймворк для написания и запуска тестов.
*   **Mockito:** Инструмент для создания стабов и моков (имитация поведения зависимостей).
*   **Spring Security Test:** Расширение для тестирования защищенных ресурсов и имитации Auth-контекста.
*   **AssertJ:** Библиотека для написания "читаемых" и понятных проверок (assertions).

---

### Что добавилось на данном этапе:

1.  **Lombok Integration:**
    *   Сущности `User` и `Task`, а также `TaskDto` переведены на аннотации `@Data`, `@NoArgsConstructor`, `@AllArgsConstructor` и `@Builder`.
    *   **Результат:** Из проекта удалены сотни строк визуального шума. Код стал лаконичным и сфокусированным на бизнес-логике.

2.  **Unit Testing Suite (JUnit 5 + Mockito):**
    *   Создан тестовый комплекс для `TaskServiceImpl`.
    *   Использование **Mockito** позволило изолировать сервис от базы данных. Теперь мы тестируем логику в чистом виде.

3.  **Security Context Mocking:**
    *   Внедрен механизм имитации авторизованного пользователя. Мы научили тесты «притворяться» залогиненным юзером через `SecurityContextHolder`.

4.  **Behavior Verification (Проверка поведения):**
    *   Использование `verify()` позволило убедиться, что сервис вызывает методы репозитория только при соблюдении прав доступа.

---

### Проверка работоспособности кода

Для подтверждения стабильности добавленного функционала выполните:

#### 1. Запуск модульных тестов
*   **Действие:** Запустить класс `TaskServiceImplTest` через IDE (IntelliJ IDEA).
*   **Ожидаемый результат:** Все тесты отмечены **зелеными галочками**.

#### 2. Валидация логики безопасности
*   **Что проверяем:** Тест `deleteTask_Forbidden`.
*   **Результат:** Система должна выбросить `RuntimeException` при попытке удалить чужую задачу.

#### 3. Тестирование асинхронной интеграции
*   **Что проверяем:** Тест `markAsDone_ChangesStatusAndCallsAsync`.
*   **Суть:** Убеждаемся, что статус меняется на `ANALYZING`, а сигнал в `TaskAnalysisService` уходит мгновенно.
