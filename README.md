# JavaTracker

## Этап 14: API Documentation (Swagger / OpenAPI 3)
На данном этапе была интегрирована интерактивная графическая система документации REST API. 
Внедрение промышленного стандарта OpenAPI 3 позволяет полностью автоматизировать координацию 
действий между бэкенд-разработчиками, фронтенд-командой и инженерами по тестированию (QA).

---

### Стек технологий проекта

#### Базовый стек:
* **Java 17 / 21** — современный LTS-релиз с поддержкой Stream API и Concurrency.
* **Spring Boot 3.x / 4.x** — основа бэкенд-инфраструктуры и контейнера бинов.
* **Spring Data JPA & Hibernate** — объектно-реляционное отображение (ORM) и работа со схемами БД в режиме `validate`.
* **Spring Security** — ограничение доступа (роли USER, ADMIN) и шифрование паролей через BCrypt.
* **PostgreSQL 15** — целевая локальная реляционная СУБД.
* **Flyway Core (Programmatic)** — программный миграционный движок с принудительным запуском через `@PostConstruct`.
* **Thymeleaf & Bootstrap 5** — шаблонизатор и фронтенд-фреймворк для построения классического Web UI.
* **Lombok & JUnit 5 / Mockito** — автоматическая генерация кода и комплекс модульного тестирования.

#### Добавлено на 14 этапе:
* **Springdoc OpenAPI UI** — стартер для автоматической генерации спецификаций OpenAPI 3 и развертывания 
* веб-интерфейса Swagger UI.
* **OpenAPI 3 Annotations** — набор семантических аннотаций (`@Tag`, `@Operation`, `@Parameter`) 
* для декларативного описания эндпоинтов REST API.

---

### Что добавилось на данном этапе:

1. **Автоматическая кодогенерация:**
    * Внедрен механизм динамического сканирования метаданных приложения во время работы JVM. 
    * Документация полностью защищена от устаревания — любое изменение сигнатуры методов в Java-коде 
    * мгновенно синхронизируется в браузере.

2. **Безопасный шлюз доступа:**
    * В классе `SecurityConfig` настроен "зеленый коридор" (`.permitAll()`) для служебных 
    * эндпоинтов `/swagger`, `/swagger-ui/**` и `/v3/api-docs/**`. 
    * Документация изолирована от общих правил блокировки Spring Security, оставаясь доступной для 
    * смежных ИТ-отделов без прохождения веб-авторизации.

3. **Локализация и семантическое описание (`TaskController`):**
    * REST-контроллер покрыт метаданными. 
    * Аннотация `@Tag` задает бизнес-группу операций, `@Operation` формирует краткие текстовые спецификации 
    * к методам поиска, добавления и удаления задач, а `@Parameter` документирует граничные условия и форматы 
    * входных переменных.

4. **Атомарное разделение представлений:**
    * Структурирован блок графических схем (Schemas) в Swagger UI. В отличие от терминала СУБД PostgreSQL, 
    * отображающего 4 физические таблицы хранения данных 
    * (включая служебную `flyway_schema_history` и связующую `user_role`), 
    * Swagger изолированно выводит строго 3 схемы сетевого обмена (`TaskDto`, `Task`, `User owner`), 
    *  координируя формат передачи JSON-объектов по HTTP-каналам.

### Проверка работоспособности кода

Для валидации корректности развертывания интерактивной документации Swagger UI выполните пошаговый сценарий:

#### 1. Запуск приложения:
* Запустите метод `main` в классе `DemoApplication` внутри IntelliJ IDEA.
* Дождитесь финальной строчки в логах об успешном запуске встроенного сервера Tomcat на порту `8080`.

#### 2. Вход на страницу документации:
* Откройте любой веб-браузер на компьютере.
* Введите в адресную строку настроенный короткий URL-путь: `http://localhost:8080/swagger`.
* **Ожидаемый результат** — отобразится графическая панель OpenAPI Definition со списком эндпоинтов трекера задач.

#### 3. Интерактивный тест-драйв REST API:
* Раскройте кликом мыши тестовый метод `GET /api/tasks/hello`.
* Нажмите появившуюся в правом углу кнопку **Try it out** (Попробовать).
* Нажмите большую синюю кнопку **Execute** (Выполнить) для отправки HTTP-запроса на бэкенд.
* **Ожидаемый результат** — в блоке *Responses* отобразится статус `200` и строка: 
* `"Привет! Наш трекер JavaRush скоро оживет!"`.

### Вывод:
Интеграция Swagger перевела проект на профессиональный уровень командной разработки. 
REST API трекера теперь имеет строго документированный контракт, выступающий в роли независимого 
"юридического договора" между бэкенд-компонентами Java и любыми потенциальными потребителями данных 
(фронтенд-приложениями, мобильными клиентами или ручными тест-кейсами QA).
